# Part A - JavaScript in one page

Think of the three files as one team:

| File | It is like | What it actually does |
| index.html | The skeleton | The bones of the page: panels, buttons, canvases - but they do nothing by themselves. |
| styles.css | The skin and clothes | All colors, positions, sizes, animations. It can make things pretty, but it cannot make decisions. |
| game.js | The brain and muscles | Every decision, every reaction to a click or swipe, all the math, the memory (saving), the sounds. |

JavaScript is a programming language that browsers understand. When you open index.html, the browser does three things, in order:

1. Builds the page from the HTML.
2. Dresses it up with the CSS.
3. Runs game.js **from top to bottom, one single time**.

That third step is the surprise for most beginners: the file only "runs through" once. So how does the game keep working for hours? Because while reading top to bottom, JS mostly **stores recipes (functions)** and **sets up listeners** ("when X happens, run recipe Y"). Then it waits. Every cut, click, timer tick or saved game is one recipe being run.

! Judge sound-bite: "The file runs once at load: it defines about 90 small functions and wires them to events. After that, the game is just events calling functions - nothing runs unless something happens."

## The five things every program does
- **Store data** in variables (the player's coins, the current order).
- **Make decisions** with if / else (did the cuts add up to 4?).
- **Repeat work** with loops (draw 28 confetti pieces).
- **Change the page** (show a toast, fill the XP bar).
- **React to events** (a click, a swipe, a 420 ms music tick).

Every one of the ~3,300 lines does exactly one of these five things. Keep this list in your head and no line will ever look like magic.

# Part B - The 8 building blocks of game.js

## B1 - Statements, semicolons and comments
A **statement** is one instruction - one sentence of the program. Most end with a semicolon `;`, like a period ending a sentence. Lines starting with `//` are **comments**: notes for humans, completely ignored by the browser.

```js
// this line is a note for humans - the browser skips it
stats.coins += 5; // give 5 coins; the ; ends the instruction
```

## B2 - Variables: labeled boxes that hold values
`const` makes a box that never gets re-filled. `let` makes a box that can change. The name is up to you.

```js
const storageKey = "chef-bolt-fair-share-v1"; // never changes
let wheelSpinning = false; // changes while the wheel turns
let cuts = []; // grows as the player cuts
```

Why not write the numbers directly everywhere? Because a **named box** explains itself: when you read `storageKey` you know exactly what it is for.

## B3 - The main kinds of values
- **Numbers**: `30`, `0.82`, `4200` - coins, XP, milliseconds.
- **Strings** (text): always wrapped in quotes: `"Pizza Bolt"`.
- **Booleans**: `true` or `false` - the answer to any yes/no question.
- **Template strings**: strings written with backticks that can inject values into holes marked `${...}`:

```js
`Cut the ${t("pizza")} into ${localizedNumber(4)} equal slices`
// -> "Cut the pizza into 4 equal slices"
```

`${}` is pronounced "fill this hole with the value of this expression". You will see it all over game.js, because every message the game shows is built this way.

## B4 - Functions: recipes with a name
A function is a **recipe**: it takes ingredients (arguments), does steps, and often **returns** one result. Defining it does nothing; **calling** it with `()` runs it.

```js
function currentLevel() { return Math.floor(stats.xp / levelsPer) + 1; }
```

Reading it out loud: "take the XP, divide by 30, chop off the decimals, add 1 - that is the level." If `stats.xp` is 64: 64 / 30 = 2.13, floor gives 2, plus 1 gives **level 3**. One tiny recipe decides the whole difficulty curve of the game.

Functions can take ingredients from outside:

```js
function shuffle(items) { ... }   // definition - just stored, nothing happens
const mixed = shuffle(missions);  // call - NOW the steps run
```

## B5 - Decisions: if / else and early exits
`if (condition) { ... }` runs its block only when the condition is true. `else` covers the false case. Conditions are comparisons: `>` `<` `>=`, plus `===` (is equal) and `!==` (is not equal).

This is the real `gainXp` from your file:

```js
function gainXp(amount) {
  const oldLevel = currentLevel();
  stats.xp += amount;
  const newLevel = currentLevel();
  if (newLevel > oldLevel) {
    missionDeck = createMissionDeck();
    questionDeck = createQuestionDeck();
    stats.coins += 20;
    setTimeout(() => showToast(`${t("level")} ${newLevel}`, true), 350); // shortened
  }
  updateProgress();
  saveStats();
  checkTrophies();
}
```

This one function is a whole story: remember the old level, add XP, compute the new level, and **only if it grew** rebuild both decks and pay the +20 level-up reward. `updateProgress`, `saveStats` and `checkTrophies` must run every time - that is why they sit outside the if.

An **early exit** is an if at the very top of a function that says "impossible - leave now":

```js
function spinWheel() {
  if (wheelSpinning || stats.wheel.charges <= 0) return;
  // ...the rest only runs when spinning is safe
```

`||` means "or". Read it as: "if the wheel is already spinning OR there are no charges, stop here." Guards like this are a big reason the game is hard to break.

## B6 - Arrays: numbered lists
An array is a list of values stored in one box. Positions (called **indexes**) start counting at **0**:

```js
["pizza", "flatbread", "chocolate"] // index 0, 1 and 2
```

The most-used array moves in game.js:

| Code | Meaning |
| cuts.push(axis) | Add one cut to the end of the list |
| missionDeck.shift() | Take the first mission out of the deck |
| missionDeck.length | How many missions are left |
| cuts.includes("horizontal") | Is this cut already made? |
| result[index] | Read or write slot number `index` |

## B7 - Objects: labeled backpacks
An object stores values under **names** instead of numbers:

```js
stats = {
  xp: 64,
  coins: 37,
  streak: 2,
  shop: { owned: [...], equipped: { cutter: "classic" } }
}
```

Read a pocket with a dot: `stats.coins` is 37. A pocket inside a pocket: `stats.shop.equipped.cutter`. Objects and arrays mix freely - `trophyDefs` is an **array of objects**, one per trophy:

```js
const trophyDefs = [
  { id: "firstOrder", key: "trophyFirstOrder", test: (s) => s.rounds >= 1 },
  { id: "rich",       key: "trophyRich",       test: (s) => s.coins >= 150 },
  // ...10 more trophies
];
```

Each trophy is pure data: an id, a translation key for its name, and a `test` function. Checking all trophies is one small loop - the trophies themselves never need special code.

## B8 - Loops: "do this N times"
A `for` loop repeats while its condition holds:

```js
for (let i = 0; i < 28; i++) {
  // runs with i = 0, 1, 2 ... 27
}
```

Read it as: "start i at 0; keep going while i is under 28; add 1 each round." `confetti()` uses exactly this loop to make 28 confetti pieces:

```js
for (let i = 0; i < 28; i++) {
  const piece = document.createElement("i");
  piece.className = "confetti";
  piece.style.left = `${Math.random() * 100}vw`;
  piece.style.background = colors[i % colors.length];
  $("#toastRoot").append(piece);
  setTimeout(() => piece.remove(), 1450);
}
```

A `for...of` loop walks through a list - here, the placeholder pairs inside the `t()` translator:

```js
for (const [name, value] of Object.entries(values))
  text = text.replaceAll(`{${name}}`, value);
```

- **Line 1**: "for each name/value pair in the placeholder object..."
- **Line 2**: "replace the `{name}` hole in the text with the real value."

That single loop turns "Cut the {food} into {n} equal slices" into a real instruction.

# Part C - How JavaScript controls the page

## C1 - The DOM and the `$` shortcut
When the browser loads the HTML, it builds the **DOM**: a live model of every tag on the page. JS reads and changes the DOM - that is how the game does anything on screen.

`document.querySelector("#pizza")` finds the element whose id is `pizza`. Because game.js does this hundreds of times, line 3 defines a shortcut:

```js
const $ = (selector) => document.querySelector(selector);
```

From then on, `$("#pizza")` means "find the pizza canvas". Two characters instead of twenty.

## C2 - Reading and changing things
```js
$("#wheelPrize").textContent = "";  // empty the prize label
$("#instruction").textContent = ... // show "Cuts made: 2 / 4"
```

`.textContent` is the raw text inside an element - change it and the screen updates. For **brand new** elements, JS builds them from nothing:

```js
function showToast(message, level = false) {
  const toast = document.createElement("div");
  toast.className = `toast${level ? " level-toast" : ""}`;
  toast.textContent = message;
  $("#toastRoot").append(toast);
  setTimeout(() => toast.remove(), 1100);
  if (!level) confetti();
}
```

Six lines, and one of the most reusable patterns in the whole file: create an element, give it a class (so CSS styles it), put text in it, append it to a container, remove it later. Toasts, confetti, shop cards, quiz buttons and modals are all built this way. **CSS makes them pretty; JS decides when they exist.**

## C3 - classList: the bridge between JS and CSS
Every element has a `classList` - the list of CSS classes attached to it. JS flips classes; CSS has rules for those classes:

| JS writes | CSS reacts |
| classList.add("hidden") | The panel disappears (display: none) |
| classList.add("shake") | The card shakes (a keyframe animation) |
| classList.add("correct") | The answer button turns green |
| classList.add("hot") | The streak flame lights up at streak 3+ |
| classList.add("coin-pulse") | The coin pouch bounces |

! Judge sound-bite: "JavaScript never paints anything itself - it flips classes and sets attributes, and the stylesheet does the painting. That separation is why themes and animations stay simple."

## C4 - Events: the heart of the game
`addEventListener` means: "when this event happens on this element, run this function." The function is called a **callback** - you hand it over now, the browser calls it later.

```js
canvas.addEventListener("pointerdown", (event) => { ... });
canvas.addEventListener("pointermove", (event) => { ... });
canvas.addEventListener("pointerup",   (event) => { ... });
```

Those three listeners ARE the cutting mechanic: pressing starts a cut, moving drags the cutter, releasing finishes it. `(event) => { ... }` is an **arrow function**: a recipe written on the spot, with no name. `event` is a small object describing what happened (where the pointer was, which pointer ID, and so on).

The full cut logic then validates the gesture (started near the center? long enough swipe? correct direction?) and snaps the cut to a fair slot - the full story is in Part E4.

## C5 - Timers: doing something later
| Tool | Meaning | Used in game.js for |
| setTimeout(fn, ms) | Run fn once, after ms milliseconds | Removing toasts (1,100 ms), the level-up toast (350 ms) |
| setInterval(fn, ms) | Run fn every ms, forever | The music scheduler tick (every 420 ms) |
| requestAnimationFrame(fn) | Run fn before the next screen frame (about 60 times a second) | The wheel spin animation, the Matrix rain |

## C6 - Canvas: painting with code
The pizza is not an image - it is drawn on a 520 x 520 `<canvas>`. JS keeps a "brush" object (`ctx`) and calls drawing commands:

```js
ctx.drawImage(pizzaImage, 0, 0, 520, 520);      // paint the food art
ctx.filter = "saturate(1.3) hue-rotate(25deg)"; // gear tint
ctx.beginPath();          // start a new shape
ctx.moveTo(260, 260);     // lift the brush to the center
ctx.lineTo(430, 260);     // drag to the edge - one cut line
ctx.stroke();             // commit the line
```

That is the whole idea: coordinates plus commands. Every cut mark, the dashed cut guide, the chocolate bar and the prize wheel are all just these commands with different numbers.

# Part D - The 5 big ideas that hold game.js together

## D1 - One private room: the IIFE
The file starts like this:

```js
(() => {
  "use strict";
  const $ = (selector) => document.querySelector(selector);
  // ...everything else, then at the very bottom:
})();
```

An **IIFE** (immediately invoked function expression) is a function that runs once, immediately. Its superpower: everything inside stays **private**. Without it, hundreds of names would leak into the browser's global scope and could collide with any other script. `"use strict"` turns silent mistakes into loud errors, which makes bugs easier to catch.

## D2 - Data-driven design: the file is mostly tables
Look at what the big constants really are:

| Constant | What it holds |
| translations | about 200 strings in both languages |
| lessonPlans | 18 lessons in both languages (steps, questions, SVG specs) |
| variants | 5 gear sets (prices, speeds, sounds, colors) |
| bonusThemes | 10 themes (prices, swatches) |
| wheelPrizes | 8 prizes (weights, labels, effect functions) |
| trophyDefs | 12 trophies (id, name key, test function) |

The functions are **generic readers** of these tables: `t()` reads translations, `renderShop()` reads variants and bonusThemes, one loop reads trophyDefs. That is why adding an 11th theme or a 13th trophy is one data line, not new logic.

! Judge sound-bite: "Ninety percent of game.js is data - lessons, translations, prizes, trophies - and the rest is generic code that reads the data. That is why two languages, 18 themes and 12 trophies did not multiply the code by 18."

## D3 - One state object plus a validated save
The entire game lives in one object, `stats`: XP, coins, streak, decks, shop ownership, wheel charges, arcade bests, trophies. The rules:
- `saveStats()` writes it to **localStorage** (the browser's built-in memory that survives reload) as **JSON** - a text format: `stats.coins` becomes `"coins": 37` in the file.
- `loadStats()` reads it back - but **never trusts it**: every number is clamped to a legal range, every gear id is checked against a whitelist, colors are regex-checked, and the three starter items are always re-granted.
- `structuredClone(defaultStats)` gives each new game a deep copy, so no two parts of the game can share a pocket by accident.

## D4 - Functions that take functions
In JavaScript, a function can be stored in a variable, put inside an array, or passed to another function. game.js leans on this everywhere:
- `canvas.addEventListener("pointerdown", handler)` - the handler is a function you hand away.
- `trophyDefs` stores `test` functions; `checkTrophies()` just calls each one: `if (trophy.test(stats)) ...`
- `setTimeout(() => toast.remove(), 1100)` - a tiny nameless recipe for later.
- `wheelPrizes[].apply` - each prize carries its own effect function, like `apply: () => addCoins(5)`.

When the wheel lands, the winning prize's own function runs. The spin code never needs to know what the prizes do - that is the point.

## D5 - Defensive details that keep it unbreakable
- **Early returns**: every handler first checks "is this legal?" and leaves if not.
- **Guards**: `orderFlowToken` is a number stamped on each order; timers left over from an older order compare tokens and ignore themselves if stale.
- **Clamps**: `Math.min(10, ...)` everywhere - wheel charges can never exceed 3, boosts never exceed 10.
- **Fallbacks**: if the pizza image has not loaded, a procedural drawing takes over; if a translation is missing, English is used; if even that is missing, the raw key is shown.

# Part E - Guided tours: real code, line by line

## E1 - The first six lines of the file
```js
(() => {
  "use strict";
  const $ = (selector) => document.querySelector(selector);
  const canvas = $("#pizza");
  const ctx = canvas.getContext("2d");
  const storageKey = "chef-bolt-fair-share-v1";
```

- **Line 1** opens the IIFE private room.
- **Line 2** enables strict mode.
- **Line 3** defines the `$` finder shortcut.
- **Line 4** finds the pizza canvas in the page.
- **Line 5** takes its 2D drawing brush.
- **Line 6** names the save slot.

Six lines, and the toolkit is ready: a finder, a canvas, a brush, a memory address. Everything after this builds on exactly these four tools.

## E2 - The translator in four lines
```js
function t(key, values = {}) {
  let text = translations[lang][key] || translations.en[key] || key;
  for (const [name, value] of Object.entries(values))
    text = text.replaceAll(`{${name}}`, value);
  return text;
}
```

- **Line 1**: define `t`. If no values were passed, use an empty object - that is what `values = {}` means (a **default**).
- **Line 2**: try the current language; if the key is missing, `||` falls back to English; if even that is missing, show the key itself. (`a || b` means "a, unless it is empty, then b".)
- **Line 3**: for every placeholder pair, replace the `{name}` hole with the value.
- **Line 4**: hand back the finished sentence.

Calling `t("cutPrompt", { food: "pizza", n: 4 })` gives "Cut the pizza into 4 equal slices" - or the Arabic version, automatically.

## E3 - The wheel: how the prize is really chosen
```js
const totalWeight = wheelPrizes.reduce((sum, prize) => sum + prize.weight, 0);
let roll = Math.random() * totalWeight;
let prizeIndex = 0;
for (let index = 0; index < wheelPrizes.length; index++) {
  roll -= wheelPrizes[index].weight;
  if (roll < 0) { prizeIndex = index; break; }
}
```

- **Line 1**: add up all the weights (they sum to 100).
- **Line 2**: pick a random number between 0 and 100.
- **Lines 4 to 6**: walk down the prize list, subtracting each weight from the roll; the moment the roll drops below zero, the prize just subtracted is the winner.

Worked example: roll = 41.3. coins5 (weight 20) leaves 21.3. coins10 (weight 18) leaves 3.3. xp15 (weight 12) leaves -8.7, which is under 0, so **xp15 wins**. A rare prize (weight 4) needs a lucky number; a common one (weight 20) wins often. The 4.2-second spinning animation afterwards is pure show - the math already decided.

## E4 - The cut gesture, told as a story
```js
canvas.addEventListener("pointerdown", (event) => {
  // validate: started near the hub? near the bar edge? -> otherwise: hint, leave
  pointerStart = point; isDrawing = true;
});
canvas.addEventListener("pointermove", (event) => {
  if (!isDrawing) return;         // ignore moves when no cut is in progress
  moveCutter(canvasPoint(event)); // drag the cutter image with the finger
});
canvas.addEventListener("pointerup", (event) => {
  // measure the swipe; validate length and direction; snap to the fair slot
  cuts.push(...); drawPizza(); isDrawing = false;
});
```

Three listeners, one shared memory: `isDrawing` and `pointerStart` remember that "a cut is happening". The pattern - record on down, follow on move, commit on up - is the standard recipe for every drag interaction in every app, game and drawing tool ever made.

# Part F - Decoders

## The punctuation decoder
| Symbol | Meaning | Example from game.js |
| ; | End of an instruction | stats.coins += 5; |
| . | "go inside" | stats.shop.owned |
| () | Run this function | shuffle(missions) |
| {} | Object / code block / template hole | { xp: 64 } or if (x) { ... } or `${n}` |
| [] | Array, or a slot in an array | cuts[0] |
| => | Arrow function: "this becomes this" | (s) => s.rounds >= 1 |
| === and !== | exactly equal / not equal | stage === "baking" |
| = versus === | = stores a value; === compares two values | x = 5 then if (x === 5) |
| ! | not | if (!isDrawing) return; |
| && and || | and / or (also "fallback": a || b) | wheelSpinning || charges <= 0 |
| ? : | a tiny if/else | level ? " level-toast" : "" |
| ++ and -- | add 1 / remove 1 | i++ |
| += and -= | add / subtract in place | stats.xp += amount |
| ... | spread: pour the items out | missions.push(...chocolate) |
| // | comment for humans | // builds the mission deck |
| Backticks + ${} | Template string: text with fill-in holes | +${n} XP |

## The error decoder (when the console turns red)
The console (press F12 in the browser) shows errors with a line number. The classics:

| Message | Usual cause |
| SyntaxError: missing ) after argument list | A bracket or brace is missing somewhere above |
| xxx is not defined | A typo in a name, or code used outside the IIFE |
| Cannot read properties of undefined | You went inside a pocket that does not exist (stats.shop.coins typo) |
| Uncaught (in promise) ... | Usually audio or storage refusing - check autoplay or permissions |

! Judge sound-bite: "We typed every line by hand, so we learned to read the console: red text plus a line number is the browser telling us exactly which sentence it could not understand."

## Ten 10-minute experiments (browser console, press F12)
Type these one at a time and watch what happens:

1. `2 + 2`, then `"pizza" + " bolt"` - numbers add, strings glue together.
2. `Math.floor(7.9)` and `Math.random()` - the two math tools the game uses everywhere.
3. `document.title` - JS can already see the page.
4. `document.body.style.background = "lightgreen"` - you just did what the theme engine does.
5. `localStorage.getItem("chef-bolt-fair-share-v1")` - your real save file, in one line.
6. `JSON.parse(localStorage.getItem("chef-bolt-fair-share-v1")).coins` - dig one pocket out.
7. `let deck = [1, 2, 3]; deck.push(4); deck` - arrays grow.
8. `const double = (n) => n * 2; double(21)` - your first arrow function.
9. `for (let i = 1; i <= 5; i++) console.log("cut " + i)` - your first loop.
10. `location.reload()` - undo all your experiments by reloading.

## Judge questions for beginners - honest, strong answers
| If a judge asks... | You can answer... |
| What is a variable? | A labeled box that holds a value, like stats.coins holding my coin total. const locks the label, let allows refills. |
| What is a function? | A named recipe: take inputs, do steps, return a result. My whole level system is one line: XP / 30, decimals chopped off, plus 1. |
| How does the game react to a swipe? | Three listeners on the canvas: pointerdown records the start, pointermove drags the cutter, pointerup validates the gesture and snaps it to a fair slice. |
| How do you keep the game from breaking? | Early returns in every handler, clamped numbers, a validated save load, and a guard token so stale timers cannot touch new orders. |
| Where is the game's memory? | One object called stats, saved as JSON in localStorage, and re-validated on every load. |
| Why is everything inside one big function? | It is an IIFE: it runs once at load and keeps all the names private, so nothing can collide with another script. |
